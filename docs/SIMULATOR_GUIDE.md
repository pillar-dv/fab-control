# FAB CONTROL

300 mm 반도체 팹의 생산층을 둘러보고, 장비 배치와 공정 순서를 바꿔 웨이퍼 한 장의 이동과 단면 변화를 관찰하는 데스크톱 웹 시뮬레이터다. [프로젝트 문서](./) · [5단계 장비 검수 기록](../assets/equipment/README.md) · [개발 체크리스트](<개발 체크리스트.md>)

## 실행

프로젝트 루트에서 Node.js 22.12 이상으로 실행한다.

```powershell
npm run dev
```

터미널의 로컬 주소에서 **생산라인 모니터** 또는 **반도체 캠퍼스**를 선택한다. 선택한 모드가 준비되면 화면이 열린다. 새 설치 환경에서는 먼저 `npm ci`를 실행한다. 프로젝트에서 자동화 도구로 설치·브라우저 검증을 할 때는 [승인 규칙](../AGENTS.md)을 적용한다. 화면에는 WebGL 2를 사용하며 실행 중 외부 모델이나 폰트를 내려받지 않는다.

## 첫 인계 관찰하기

1. 페이지를 열면 **절연막 패터닝** 라인이 자동으로 운전한다. 천장 운송차가 스토커에서 닫힌 FOUP를 들어 올려 증착기 앞에 내려놓는다. 두 FOUP가 스토커로 돌아오면 다음 웨이퍼로 새 회차를 시작한다. **정지**는 현재 위치와 예약을 유지하고 **재생**은 그 지점부터 이어간다.
2. **FOUP-01 → 따라가기**로 선택 웨이퍼에 카메라를 맞춘다. 장비 외장이 열리고 도킹, 슬롯 인출, 로드록과 진공 로봇 인계를 차례로 볼 수 있다. **다음 동작**은 다음 기록 시점까지 이동한 뒤 일시정지한다.
3. **입구**에서 공장 밖의 품목 표지를 읽고, **등각·상면·하면·현장**으로 시점을 바꾼다. 마우스 왼쪽 드래그는 회전, 오른쪽 드래그는 이동, 휠은 확대·축소다. 웨이퍼를 따라가는 중에 등각·상면·하면을 바꿔도 추적이 이어진다. 하면에서는 생산층 바닥과 장비 하부를 잘라 이송 중인 웨이퍼를 아래에서 비춘다. 뷰 오른쪽 위의 자 아이콘으로 치수와 인계 축을 확인한다.
4. 품목을 바꾸면 해당 시나리오가 새 회차를 시작한다. 생산층 입구 표지, 공정 목록, 장비 종류·배치와 실행 경로가 함께 바뀐다. 운전 또는 정지 상태는 품목을 바꿔도 이어진다. 외부 운송 횟수는 웨이퍼가 들어 있는 **FOUP 한 개 기준**이다.

## 시나리오 범위

### 식각기 한 대를 추가해 새 라인으로 운전하기

1. **절연막 패터닝 → 라인 편집**을 연다. 장비를 평면에서 끌면 오른쪽 3D 미리보기에서 장비와 인계점이 함께 움직인다. 편집하는 동안 적용된 라인은 직전 상태로 운전한다.
2. 평면에서 **ETCH-01 → 복제**를 누른다. 빈 위치에 **ETCH-02**가 생긴다. 오른쪽 **5단계 절연막 식각**의 처리 장비를 **ETCH-02**로 바꾸고 **라인 적용**을 누른다.
3. **재생** 또는 **다음 동작**으로 진행한다. 식각을 배정한 2호기로 FOUP가 이동하고, 감광막 제거를 위해 1호기로 한 번 더 운반된다. 기본 배치의 FOUP당 외부 운송 4회가 이 구성에서는 5회가 된다. 공정 목록, 3D 표지와 이벤트 기록에서 장비 번호를 확인할 수 있다.
4. 다시 편집을 열어 **CVD-01**을 선택하고, 장비 기종을 **절연막 증착기**로 바꿔 **선택 기종으로 교체**한다. **STK-01**의 중심 X를 **5.5 m**로 옮겨 적용하면 새 스토커 위치에서 다음 사이클이 시작된다.

장비 중심 좌표는 북서쪽 바닥을 원점으로 한다. 인계점은 평면의 점으로 표시한다. 북열 포트 장비는 Z 4.5 m에서 남향, 남열 포트 장비는 Z 13.5 m에서 북향이어야 직선 레일에 연결된다. 노광기는 같은 방향의 트랙과 브리지가 맞닿아야 한다. **물류 시설**에서 출발·복귀 스토커, OHT 가용 대수 1~6대, 순환 레일 네 구간을 편집한다. 기준 라인에는 3대, 품목별 라인에는 4대를 기본 배치했다.

**되돌리기**는 마지막 편집을 취소한다. **취소**는 초안만 버린다. **라인 적용**은 장비 겹침과 공정·레일 연결을 확인한 뒤 선택한 스토커에서 새 회차를 시작한다. 적용한 배치는 현재 페이지에서 품목별로 유지되며 새로고침하면 기본 배치로 돌아간다.

### 장비 도감과 설비 단면

**장비 정보 → 장비 도감**에서 공정과 제조사·기종을 고르면 정면·우측면·후면·사시도, 공개 사양과 모델 외곽을 볼 수 있다. **3D 모델 받기 · GLB**로 모델을 저장한다. 기본 라인의 FOUP 문, OHT 승강부, 내부 이송 로봇 3종에는 재생 가능한 동작이 들어 있다. [공정별 반도체 장비 도감](<공정별 반도체 장비 도감.md>) · [기본 장비 검수 기록](../assets/equipment/README.md)

**설비 단면**을 누르면 생산층 아래에 진공 펌프와 배관, 위에 팬필터와 급기 덕트가 나타난다. 펌프와 팬필터에 커서를 올리면 역할과 모델 치수가 표시된다. 같은 화면에서 드래그로 회전하거나 **등각**으로 돌아갈 수 있다.

### 장비 정보와 식각 비교

장비에 커서를 올리면 외곽이 강조되고 참조 모델, 역할, 폭·깊이·높이가 표시된다. 3D 모델에서 계산한 외곽 치수와 공개 제조사 사양을 따로 표시한다. 빈 공간으로 이동하면 정보가 닫힌다.

**웨이퍼 단면**을 열면 선택 중인 웨이퍼의 위치와 재료가 보인다. **공정으로 이동**에서 관찰할 단계를 고르거나 **식각 직전으로**를 눌러 되돌아간다. **기준 시간 실행**과 **짧은 시간 실행**은 같은 웨이퍼·같은 층의 식각 시작 상태에서 각각 출발하며 식각이 끝나면 자동으로 멈춘다. 두 결과는 같은 위치·배율로 남는다. 초기 절연막 두께 1에 대한 상대값으로 기준 시간의 개구부는 0, 절반 시간의 개구부는 0.5, 보호 영역은 모두 1이다. 품목 전환이나 처음부터 다시 시작하면 실습 결과가 초기화된다.

### 품목별 경로

- **절연막 패터닝**은 증착, 도포, 노광, 현상, 식각, 감광막 제거의 여섯 단계다. FOUP는 네 번 이동한다. 트랙과 노광기 사이, 식각과 제거 챔버 사이에서는 웨이퍼만 이동한다.
- **CPU**는 배선 홈 식각 → 장벽·시드막 증착 → 구리 전기도금 → CMP → 배선 연속성 검사로 이어진다. [Applied Materials 배선 공정](https://ir.appliedmaterials.com/static-files/109fae11-37aa-4eb4-993a-f82f880dfc3b)
- **DRAM**은 저장 노드를 패터닝한 뒤 ALD 유전체와 상부 전극을 형성하고 검사한다. [Micron DRAM 셀](https://www.micron.com/content/dam/micron/educatorhub/intro-to-memory/micron-intro-to-memory-presentation.pdf)
- **차량용 MCU**는 내장 플래시 주변 회로의 패터닝·이온 주입·활성화 열처리·배선과 전기 검사를 보여 준다. [ST SPC58 E](https://www.st.com/en/microcontrollers-microprocessors/spc58-e-line-mcus.html)
- **3D NAND**는 교대 적층막을 만든 뒤 깊은 채널 홀을 식각하고 채널 내부 저장막과 접점 금속을 형성한다. [Kioxia BiCS FLASH](https://www.kioxia.com/en-jp/rd/technology/bics-flash.html)
- **적층 이미지 센서**는 별도로 준비된 픽셀·로직 웨이퍼의 접합, 후면 박형화, 컬러 필터·마이크로렌즈, 광학 검사와 전기 검사를 보여 준다. [Sony 후면조사 구조](https://www.sony-semicon.com/en/technology/is/back-illuminated.html) · [onsemi 센서 생산망](https://www.onsemi.com/company/newsroom/blog/automotive/managing-risk-in-automotive-image-sensor-supply-chains)
- **실리콘 전력 MOSFET**은 에피층 준비를 끝낸 300 mm 실리콘에서 셀 패터닝과 주입·활성화, 앞면·후면 전극, 전기 검사로 이어진다. [Toshiba 전력소자 제조](https://toshiba.semicon-storage.com/eu/semiconductor/design-development/innovationcentre/articles/TCM0770_Excellence_in_Power_video_interview.html)
- **아날로그·전력 IC**는 BCD 공정의 웰 패턴과 이온 주입, 활성화 열처리, 금속화·전기 검사를 보여 준다. [Hua Hong 공정 포트폴리오](https://www.hkexnews.hk/listedco/listconews/sehk/2025/0408/2025040800831.pdf)

- **GPU**는 절연막이 준비된 인터포저에서 배선 패턴을 형성하고 구리를 채운 뒤 평탄화·세정·결함 검사와 전기 검사를 거친다. [TSMC CoWoS](https://3dfabric.tsmc.com/english/dedicatedFoundry/technology/cowos.htm)
- **NPU**는 엣지 AI SoC의 보호막 접점을 열고, 조립에 쓰일 범프 하부 금속을 형성한 뒤 광학·웨이퍼 전기 검사를 진행한다. [NXP i.MX 93 데이터시트](https://www.nxp.com/docs/en/data-sheet/IMX93CEC.pdf)

감광막 도포·노광·현상은 여러 품목에서 재사용되는 공정군이다. 그 뒤에 연결되는 장비와 배치는 제품 구조에 따라 바뀐다. 10개 시나리오는 제조사 공개자료에 기반한 대표 모듈을 다룬다. 36 × 18 m 배치와 공정 시간, 차량 대수는 실습용 가정이다. [글로벌 팹 공개자료 조사](<글로벌 반도체 팹 공개자료 조사.md>) · [공정별 장비 도감](<공정별 반도체 장비 도감.md>) · [조달부터 후공정과 출하까지](<반도체 공급망과 공장 운영 조사.md>)

운송차는 대기 지선에서 호출된다. 본선 합류부터 인계와 복귀까지 차간 간격을 예약하며, 같은 인계점이나 스토커를 두 로트가 동시에 점유하지 않는다. 운송 경로가 안전하게 분리되면 여러 운송차가 병행 운행한다.

### 생산 지표와 그래프

생산라인 모니터의 **지표 확인**에서 시간당 생산량, 재공품, 픽업 대기 P95, 장비 반출 대기를 바로 볼 수 있다. 지표를 선택하면 전체 운전 또는 최근 시뮬레이션 1시간의 그래프가 열린다. 그래프의 시점 슬라이더로 과거 값을 읽고, **설비**에서는 라인 전체 또는 장비 한 대를 고른다. 품목을 전환하면 **운전 기록**에서 품목별 마지막 전환 전 기록을 선택할 수 있다.

생산 수량은 전체 공정을 마치고 스토커에 복귀한 추적 웨이퍼를 기준으로 한다. 시간당 생산량은 누적 완료량을 시뮬레이션 경과 시간으로 나눈 환산값이다. 8시간 교대와 24시간 일자는 운전 시작을 기준으로 나눈다. 납기 준수율의 분모에는 완료 건과 기한이 지난 미완료 건을 넣는다. **공정 종료부터 다음 시작 P95**는 설비 사이의 전체 대기·운송 시간이며, **운송 요청부터 안착 P95**는 다각화 실험에서 개별 OHT 운송 한 건의 시간을 보여준다. 시뮬레이션을 처음부터 시작하면 현재 운전의 집계와 수동 입력 기록을 초기화한다.

**품질**, **정비**, **자원·비용** 지표는 측정값 입력에서 구간별 증가분을 기록한다. 검사·양품 다이와 재작업·폐기 수, 고장·복구 시간, 전력·용수·비용을 입력하면 수율, MTBF·MTTR, 단위당 사용량과 비용을 계산한다. 현재 페이지에서 운전 기록을 확인할 수 있다.

### 다각화 실험

**생산라인 모니터 → 다각화 실험**에서 두 운전에 동일한 투입과 장애 조건을 적용한다. **대안을 기준과 동일하게 설정**한 뒤 한 가지 정책만 바꾸면 그 효과를 비교할 수 있다.

- **선로와 장애.** 순환선, 병목 구간 우회선, 반대 방향 복선, 스토커 인계 이중 루프, 층간 리프터 이중 루프를 고른다. 복선 차량은 지정 분기에서만 선로를 바꾼다. 인계형은 각 루프의 OHT가 별도로 달리고 FOUP만 옮긴다. 층간 리프터 1~2대와 양편 인계 포트를 예약한다. OHT-01, 본선·보조선 한 구간, 로드포트, 첫 번째 인계 장치를 지정 시간에 멈출 수 있다. 폐쇄 중 출고 스토커에서 왕복 가능한 장비 수와 재개 후 해당 자원의 첫 사용 시각을 표시한다.
- **투입과 레시피.** 단일 또는 혼류 품목, 품목 비중, 투입 집중, 난수 시작값과 투입 편차를 설정한다. 품목의 공정 순서를 위·아래 버튼으로 편집하고 선택한 설비를 지정 횟수만큼 재방문할 수 있다. 같은 설비를 연속 방문할 때는 인근 버퍼에 로트를 내려놓고 돌아온다. 공유 배치에서는 같은 설비군을 쓸지, 가공 동작도 같아야 하는지 정한다. 시험 로트와 빈 FOUP를 추가해 생산 물량과 별도로 집계한다.
- **배차와 버퍼.** 빈 차량을 출고 지선에 두거나 확정 요청 또는 완료 예측을 기준으로 재배치한다. 예측 배차는 곧 비는 차량도 비교하며, 예측 오차를 바꿔 실험할 수 있다. 예약 반영 도착시간과 정적 최단거리를 비교한다. 출발 장비 대기, 로드포트 선예약, 근거리 버퍼, 중앙 스토커, 직송 목표 비율을 선택한다. 직송 실적은 포트·버퍼 가용성에 따라 목표와 달라질 수 있다.
- **병렬 장비와 챔버.** 공유 장비 2대 조건에서 배정 건수 균등화와 외부 운송·장비 내부 가공의 예상 완료시간을 비교한다. 두 로트 공유 시 호환되는 가공 동작 순서의 로트가 챔버를 함께 쓴다. 로봇은 단일 암 또는 이중 암으로 교환하며, 선택 장비의 **장비 내부 보기**에서 같은 시점의 웨이퍼 투입·가공·회수를 확인한다.
- **그래프와 이력.** **기준·대안 비교**를 실행하면 타임라인과 그래프가 열린다. 시간당 완료 웨이퍼는 전체 모듈을 마친 생산 로트를 기준으로 계산한다. 운송 P95는 완료한 운송을 집계하며, 미완료 건수와 잔여 대기는 별도 지표다. **품목별 운송과 로트 이력**에서 생산·시험 로트, 빈 FOUP와 빈 차량의 출발지·목적지, 로트별 배차 및 공정 시각을 확인한다. **1~6대 차량 비교**는 같은 난수 시작값으로 기준·대안을 반복하고, 목표 처리량과 대기 한도를 모든 반복에서 만족한 최소 대수를 표시한다.
- **레시피 최대 대기시간 제어.** 품목과 두 공정, 허용 시간을 지정한다. 기준은 제한 위반을 집계하고, 대안은 제어를 켜면 투입 보류와 기한 순 배차를 적용한다. 한도를 넘을 것으로 판단되거나 실제 넘은 로트는 지정한 재작업 또는 보류 경로로 보낸다. 재작업은 한 차례 실행한다.
- **설비 정비와 고장 실험.** 대상 설비 한 대의 예방정비 시작·시간, 모형 고장 간격과 복구 시간을 설정한다. 대안에서 예방정비 시각을 움직이고 같은 난수의 고장 하에서 가용률, 가공·대기 시간, 평균 고장 간격과 평균 복구 시간을 비교한다.
- **현장 로그 불러오기와 비교.** `time,event,asset_id,carrier_id,lot_id,wafer_id,task_id` 열이 있는 익명화 UTF-8 CSV를 읽는다. 제공되는 예제로 형식을 확인할 수 있다. 현장 설비와 대응 모형 설비를 선택하면 공통 관찰 구간의 픽업·안착 P95, 가공률과 표본 수를 나란히 볼 수 있다. 로그 재생 및 비교는 브라우저에서 수행한다.

장비 사양, 처리 시간과 비교 지표는 연구의 실험 조건을 적용한 모형이다. 두 루프 간 인계에는 루프별 차량이 필요하다. [연구 배경과 판정 기준](<반도체 생산라인 다각화 연구.md#fab-control-적용-실험>)

## 캠퍼스 운영

시작 화면에서 **반도체 캠퍼스**를 열면 600 × 400 m 가상 부지에서 GPU 서버 모듈과 엣지 NPU SoC 주문을 운전할 수 있다. 주문 묶음과 수량, 가동 생산동, 구역당 OHT, 하역 도크, 유틸리티 회선, 시험 설비와 출하 경로를 설정하고 **시나리오 적용**을 누른다. **재생**, **다음 기록** 또는 시간 슬라이더로 진행한다. **처음 화면**으로 돌아갔다가 다시 열면 같은 탭에서 기존 운전과 편집 상태를 이어 볼 수 있다.

- **부지와 상세 시설** · 캠퍼스에서 A·B 생산동, C동 예정 부지, 중앙 유틸리티와 후공정 건물을 선택한다. **공급망**에서 외부 소재·HBM 공급사, 유통센터, 보드 조립사와 고객사를 본다. 시설을 골라 **선택 시설 열기**를 누르거나, 내부 보기에서 시설 선택을 바꾼다. 작업 기록이 있으면 해당 시설의 장비와 이송 동작이 자동으로 재생된다.
- **시설 자동 재생** · 상세 보기에서는 시뮬레이션 시간 6배속으로 선택 시설의 작업 구간을 반복한다. **정지**를 누르면 현재 자세에서 멈추고, 시간 슬라이더나 **다음 기록**으로 대기 구간도 볼 수 있다. 도크·자동창고·다이 절단·조립·시험·포장 같은 시설에 동작 단면을 적용했다. [시설별 추가 조사와 출처](<캠퍼스 시설 에셋 추가 조사.md>)
- **팹 내부** · A·B동, 상부 공조층, 클린룸, 서브팹과 유틸리티층을 고른다. **생산 구역**을 선택하면 품목 라인 한 개를 확대해 본다. 공정 분류로 장비를 찾고 **장비·챔버 단면**과 **다음 장비 가동**으로 각 챔버의 웨이퍼 투입·가공·회수를 관찰한다.
- **레일 편집과 병목 지도** · 생산층의 **레일 편집**에서 분기를 이동하거나 연결을 해제하고, 구역 스토커 위치·슬롯과 장비 로드포트를 조정한다. 적용하면 편집된 경로로 운송을 다시 예약하며, 왕복 불가 포트와 기본·편집 배치의 성과를 비교한다. **레일 점유 색상**을 켜면 점유 시간이 긴 구간을 3D 평면에서도 확인할 수 있다.

- **입고와 공급** · 발주와 공급사 로트를 대조하고 검사 승인 후 재고에 적치한다. **GPU 웨이퍼 입고 격리**에서는 부적합 로트를 창고에 격리하고 대체 로트로 투입한다. **유틸리티 투입 보류**에서는 복구 전까지 새 팹 투입을 멈춘다.
- **웨이퍼 맵과 패키지** · 양품 다이만 조립에 배정한다. GPU는 인터포저, 연산 다이, HBM과 기판이 모두 모일 때 조립한다. 엣지 NPU는 SoC 다이와 기판으로 플립칩 조립을 진행한다. 최종 시험에서 일부 제품을 재시험하고 불합격 패키지는 출하에서 제외한다.
- **포장과 고객 인도** · GPU 모델은 트레이, NPU 모델은 테이프·릴에 담는다. 수량·라벨 대조와 봉인을 거친 상자는 완제품 창고에서 고객 직송, 지역 유통센터 또는 GPU 보드 조립사 경로로 나간다. 출하 상자가 모두 인도된 뒤에는 **출하 상자와 반품 추적**에서 상자를 선택해 반품을 접수할 수 있다. 상자에서 패키지, 다이, 웨이퍼와 공급사 로트까지 추적하고 해당 로트의 잔여 재고를 격리한다.

- **동별 생산 구역** · 각 동에 생산라인 1개 또는 2개를 설치하고 구역마다 GPU 또는 NPU를 배정한다. 각 구역에 품목별 장비 두 열, 중앙 작업 통로, 스토커와 천장 순환선을 갖춘다. A동만 가동할 때 자동 배정은 1구역 GPU, 2구역 NPU다. A·B동 가동의 자동 배정은 A동 GPU, B동 NPU다. 할당할 구역이 없는 주문은 **구역 배정 대기**로 표시된다.
- **OHT 운전** · 구역당 1~6대의 전용 OHT를 배치하며 기본값은 4대다. 시뮬레이션의 예약 기록에 따라 각 차량은 담당 라인에서 FOUP를 인계하고, 공동 입·출고 스토커로 연결되는 본선도 이용한다. **팹 평면**에서 구역 간 연결을 확인할 수 있다. 현업 장비 열과 이송선 배치 구조를 참고한 교육용 모형이며, 공장별 작업·정비 접근 공간과 장비 요구사항에 따라 실제 배치는 달라진다. [Georgia Tech의 팹 물류 연구](https://msse.gatech.edu/publication/TSM_metamodeling_batarseh2010.pdf) · [Daifuku 천장 운송 시스템](https://www.daifuku.com/ir/assets/pdf/library/annualreport/profile/profile2021_en.pdf)

**HBM 지연 예시**에서는 HBM 입고를 950초 늦춘다. **정상 운전과 최종 지표 비교**는 같은 설비 구성에서 지연·격리·장애 조건의 효과를 비교한다. 새 레일의 주행 시간을 반영해 캠퍼스 예시의 납기와 ATE 정지 구간을 다시 설정했다. **생산동·시험동 증설 비교**는 같은 주문, 장애, 동별 생산 구역과 OHT, 공통 관찰 종료 시점으로 A동, A·B동, A·B동과 ATE 2대를 비교한다. 도크나 시험·조립에 대기가 생기면 주문 아래에 해당 시설 바로가기가 나타난다. 웨이퍼 맵과 검사 판정은 재현 가능한 모형 데이터이며 주문당 한 상자를 출하한다. ## 코드와 검증

[모델링 기준](../fab-model-reference.json)은 치수와 설계 좌표, [시뮬레이션](../src/simulation.ts)은 운송 예약·공정 상태·이벤트 시간, [3D 장면](../src/scene.ts)은 장비와 움직이는 부품의 표현, [카메라](../src/camera.ts)는 관찰 조작을 담당한다.

```powershell
npm test
npm run build
```

브라우저 검증은 빌드 후 `FAB_BROWSER` 환경 변수에 설치된 Chrome 또는 Edge의 실행 파일 경로를 지정하고 `node tests/browser.smoke.mjs`를 실행한다. 테스트가 로컬 서버를 열고 프로젝트의 `.qa/`에 검증용 프로필과 화면 캡처를 만든다.

7단계 통합 시연과 1080p 60초 측정은 같은 환경 변수로 `node tests/acceptance.browser.mjs`를 실행한다. 측정값과 화면 캡처는 `.qa/acceptance/`에 저장된다. 기준 노트북에서 실행할 때는 `FAB_ACCEPTANCE_DEVICE`에 모델명을, `FAB_ACCEPTANCE_OUTPUT`에 `acceptance-laptop`을 지정해 노트북 측정값을 기록한다. 질문과 평가 기준은 [입문자 실습 검수](<입문자 실습 검수.md>)에서 확인한다.

장비 정보나 형상을 수정한 뒤에는 같은 `FAB_BROWSER` 설정에서 `npm run assets:equipment`를 실행하고 다시 빌드한다. 로컬 렌더러가 기본 라인의 인계 공간을 검사하고, `assets/equipment/<공정>/<제조사-기종>/`에 GLB와 네 방향 PNG를 저장한다. 기종별 이미지·모델 경로는 장비 색인과 공정별 도감에서 확인한다.
